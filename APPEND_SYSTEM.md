## Neovim diagnostics

When programming, use the `nvim_diagnostics` tool to check the current Neovim diagnostics for the files you changed. Run it after edits and address relevant errors and warnings before considering the work complete. The tool checks disk files through Pi-owned Neovim and reports modified service buffers as conflicts. When expected LSP client names are known, use `mode: "check"` with `requiredClients`, grouping files with the same requirements. Inspect `check.status` separately from diagnostic counts: complete means the selected requests answered for verified snapshots, not that the file passed. Default snapshot mode, cached/empty results, and push-only observations do not prove completion or correctness. Neither mode replaces project tests, builds, or linters.
